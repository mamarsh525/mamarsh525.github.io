Factory

  • The Factory Method is a creational design pattern that defines a method/interface for creating objects, but lets subclasses decide which concrete class to instantiate.
  • It improves loose coupling by separating object creation from object usage, so the client code doesn’t depend directly on specific classes.
  • It makes systems easier to extend: you can add new product types by adding new concrete products/factories, often without changing existing client code (supports the Open/Closed Principle).
  • It’s helpful when object creation is complex or varies based on conditions (instead of putting lots of if/else + new logic inside the client).
  • Common real-world uses include creating components dynamically in things like browsers (renderers/plugins), Android activity creation, payment processors, and game object spawning.
  • Main components are: Product (interface/base class), Concrete Product, Creator/Factory (declares the factory method), and Concrete Creator/Factory (implements the method to return the specific product).
