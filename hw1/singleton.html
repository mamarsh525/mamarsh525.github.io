Singleton

  • The Singleton pattern guarantees that a class can be instantiated only once and that the same instance can be accessed throughout the program.
  • It’s useful when you want centralized control over a shared resource (like configuration, logging, or a database connection).
  • A key benefit is avoiding the accidental creation of multiple objects, which can waste memory or create conflicting state.
  • Common real-world uses include logging systems, configuration managers, database connection managers, and thread pools.
  • Typical Singleton structure includes a private constructor, a static variable to store the single instance, and a static method (like getInstance()) to return it.
  • There are multiple implementation approaches (lazy, eager, synchronized/thread-safe, double-checked locking, static inner class, enum), each balancing simplicity, performance, and thread safety.
